# CAD 图纸自然语言受控修改 Skill

把用户的一句话需求，转成对 DWG 的**受控几何修改**，交付原样黑白、CAXA/SolidWorks 可打开的 DWG。工作台 `engineering-drawing-ai` 已把本 skill 的规则封装进 `skill/rules.json` 并接入执行引擎。

## 何时使用
- 用户说"把风罩高度改成 450""接线盒往右挪到 290""轴伸加 15"这类口语需求
- 上传 TD50-40G 或同类电机安装图，要求按参考图/按数值修改

## 铁律（违反必错，都是踩坑换来的）
1. **数值只信用户口语和原始 CAD，绝不凭截图目测。** 移动量必须从原图尺寸线量取。
2. **主体样子不能动。** 只改明确要求的实体，范围外 handle 级零改动，实体数零增删。
3. **彩色标注只进对照图，绝不混进交付 DWG。** 交付 DWG 保持原图黑白样式。
4. **原图尺寸标注保留，但 770 随 H2 联动**：297/175/105/400/200/118kg 全部保留，297 不是 D2 不能替换；**H2 改动时总高 770 必须联动改成 `H2+175+105`**（如 443→723），这是原图黑色尺寸数字，要写进交付 DWG，不是彩色标注。
5. **看懂软件目标**：交付物是 CAXA、SolidWorks/eDrawings 能正常打开的 DWG（ODA 写 AC1032）。

## 三条规则的定标（关键，别用错）
完整常量见 `rules.json`。最容易错的三点：
- **297 尺寸线 C55 必须排除出 H2 变形**：它是原图风罩宽度标注（y≈1495），不是风罩实体。H2 降低风罩顶时若把它一起下拉，会与"297"文字（C58，y≈1521）散架、尺寸线悬空压到风罩顶盖上。用户要求 297 标注保持完整原样，`EXCLUDE_FROM_H2={"C55"}`。
- **H2**（轴向，红色）：轴向定标 K_V=1.9523（770mm）。**原 H2=490mm**（尺寸链 490+175+105=770，反推法兰贴合面 y=544.55；绝不能用 y=643.8，那会把原值算成 439、让风罩反向升高）。位移 = `(目标-490)×K_V`，443 时为 -91.8 单位（降低 47mm），风罩顶帽整体(y≥1321)一起下移。目标指"法兰贴合面→风罩最高点"，不是风罩自身长度。**总高联动**：H2 改后右侧 770→`H2+175+105`（443→723），尺寸线顶端随风罩顶下移，175/105 不动。
- **C5A 顶帽引出线必须随 H2 一起下移**：C5A（基线 y≈1375.6，x=51153→52103，从电机轴线到右总高尺寸线）与顶帽线 9FD/A06 同高，是一条顶帽高度引出线。它 x 跨度 950(>700) 且右端越过风罩右壁，会被 x范围+长线 双重规则排除——若漏掉，9FD/A06 下移到 1283.8 而 C5A 留在 1375.6，线就与顶帽断裂、悬空在半空（用户在 eDrawings 红框圈出的"错线"）。**修复**：H2 循环后单独把 C5A 整体下移 `_delta_h2`，与 9FD/A06 齐平、右端仍搭总高尺寸线（C5A 与 C5C 顶端始终保持原图 35 单位高差）。
- **D2**（径向，蓝色）：径向定标 **必须用 297 尺寸线本身长度 370.7 单位**，K_H=1.2481。**绝不能用风罩左右壁间距 440.7**——那会把盒子从中间劈开撕成两半（历史 bug）。当前 D2 实测 281.8mm，改 294 只需外移约 15.3 单位。
- **轴伸**（橙色）：新轴伸 = 江潮标准轴伸 E + N mm，沿电机轴线向泵侧伸出，N×K_V 单位。**本图未清楚显示完整轴端**，需在电机图确认轴肩与真正端面。键槽、435 基础边、虚线框内支架/法兰都不拉长，也不加到 H2。不得串联到 H2。

## 对照图标注（用户要求"标出来让看到"）
- 全图缩放会让标注文字重叠看不清；工作台另出 **三处改动放大图**（viewport=(50280,52250,280,1520)，fs_ann=16），下载项 `zoom.png`。
- D2=294 蓝色标注按用户手绘样式：水平尺寸线（电机轴线→接线盒最外端），**右端画向上箭头 + 竖线落到接线盒外盖底边（y≈737）**作为"最外端"投影界线，④文字居中于水平线上方；不要画成两端箭头+竖线落到盒顶。量的是径向伸出量，不是盒高，也不动原图 297。
- H2=443 红色竖直尺寸线（法兰面→风罩顶）、轴伸+20 橙色引出框、总高 723 黑色原位数字，都在这张放大图里清晰呈现，互不重叠。

## 旋钮座保护（最容易复发的 bug）
接线盒旋钮（同心圆 AB5/AB6）有一个**完整梯形连接楔**连到盒子边框。D2 外移时：
- 旋钮座是本体固有件，**整体不随外移**。
- 判定：实体中心落在 `x∈[51350,51420] 且 y∈[985,1040]` 的直接排除。
- `cable_neck` 判定的 y 下限必须 ≥1040；若写成 980 会把 y≈1009 的旋钮座误卷入，锯出"<"形楔。
- 只移圆弧不移斜线 = 旋钮座撕裂。整盒刚体平移 = 盒子脱离电机。两者都错。

## 操作流程
1. 解析意图：调用 `src/intent_parser.py`（或工作台 `/api/parse-intent`），把口语转成 `{targets, enabled, summary, questions}`。有追问先问清楚。
2. 用户上传 DWG（只读保存）→ 工作台解析实体、知识库匹配。
3. 展示计划让用户确认（数值、对象、不变量、禁止项）。
4. 执行：`geometry_modifier.apply(src, dst, targets=..., enabled=...)`。参数化入口在 `apply()`，默认 targets 为 443/294/20。
5. 五道质检：audit 0 错误、非预期改动 0、原标注全保留、实体数不变、eDrawings 可重开。
6. 对照图：`apply(..., annotate=True)` 生成带参考图风格彩色标注的副本，只用于 `gen_compare` 出图；交付 DWG 用无标注版。
7. ODA 导出 DWG(AC1032) 交付。

## 换图纸怎么办
定标常量是这张图实测的。换型号时必须：
- 从原始 CAD 量取对应尺寸线**端点**（不是轮廓边界，箭头内缩约 35 单位）
- 与方案文档的 from/to 数值交叉验证
- 更新 `rules.json` 的 calibration 段与 `geometry_modifier.py` 的常量区
- 旋钮座/图框排除区按新图重新测定

# 第二条链：标注换算与显示修复（25QYL-2SL 同类图）

工作台还封装了第二类需求：**图形和图框绝对不动，只改标注/单位/文字显示**。规则见 `skill/annotation_rules.json`，执行引擎 `src/annotation_engine.py`。与上面的几何变形链并列，工作台按自然语言自动分流。

## 何时用
用户说"把标注改成 1:1 实测""全改成 cm""以 610 为基准统一""这两个数字挤在一起看不清、小数点和数字分开、标在蓝线上"——这类不含 H2/D2/轴伸的标注需求。

## 四种换算模式（用户口语 → mode）
- **1:1**（最终定版）：标注 = 图形实测跨度 × 1，1 图形单位 = 1mm。例 610→144.3、284→70.6。
- **1:4**：标注 = 实测 × 4 取整 mm（GB/T 14690 标准比例）。
- **base**：以某条为真实尺寸定标 K=基准值/该条实测，其余 = 实测×K（610 基准 K≈4.2286）。
- **cm**：纯数字长度标注 ÷10 加 cm；规格类不动。

## 铁律（三轮截图返工换来的）
1. **单位默认 mm**：机械制图国标不写单位即 mm；610mm=61cm 符合泵总长，610cm 荒唐。
2. **规格类保护**：G1 / G3/4 / 4-Φ11 一律不改。
3. **DIMENSION 文字两处同步**：实体 `dxf.text` 和其 geometry 块内 MTEXT/TEXT 都要改，否则 ODA/eDrawings 显示旧值（历史坑：只改实体残留 255/291）。
4. **竖向标注字符挤压的根因是实体类型，不是位置**：eDrawings 把 DIMENSION 里 rot=0 的 MTEXT 强制竖排时压扁字符（62.2 的 6/2/小数点叠一起）。**推位置没用**——推远会飘、推到 x=285 会压绿色图框线。正解是把 MTEXT 换成 **TEXT + rotation=90**（和图上 36.4/70.6/53.6 同款），字高 2.5，贴尺寸线左侧 1.5。改完用 ODA 把 DWG 转回 DXF 验证仍保留 TEXT rot=90（商业内核互认）。
5. **从原始基线重跑**：output 中间文件常被清理，务必从 `input/25QYL-2SL.dwg` 重建 clean.dxf 再换算，绝不二次换算。

## 质检四道
audit 0 / 图形 LINE/ARC/CIRCLE 逐条零改动（2665 条）/ 实体数 2684 不变 / 规格类保留。

## 验证命令
```
python src/annotation_engine.py 1to1 output/25QYL-2SL_clean.dxf output/test.dxf
```
工作台内置示例：点"25QYL 标注换算"按钮，或说"把标注改成 1:1 实测并修复竖向标注重叠"。

# 第三条链：真实毫米几何标定（25QYL-2SL 定版）

第二条链只改标注、图形保持原图单位；如果用户要求**真实毫米版**，则走 `src/real_mm_engine.py`，几何、图框和标注一起进入毫米坐标。

## 何时用
用户说"真实毫米版""实物尺寸""总长 610mm""总高 284mm""1 图形单位 = 1mm"。

## 处理顺序
1. 识别两条总高标注：左侧 284 为基准，右侧 291 对齐到 284（绕两视图公共底边压缩）。
2. 用总长基准实测 144.2571 求 `kx = 610 / 144.2571`。
3. 用总高基准实测 70.5571 求 `ky = 284 / 70.5571`。
4. 对模型空间、图块定义、DIMENSION 显示块统一做 X/Y 标定，圆弧转椭圆。
5. 量取两视图实体外廓；右视图若因标注悬空而偏矮（275.6），绕底边校正到 284.0，并让两视图底边同线。
6. 重新量取每条尺寸线并回写标注；竖向 DIMENSION 文字换成 `TEXT + rotation=90`，字高与间距按毫米比例放大。
7. 清理 paper space 的 `WatermarkLayer` / `Evaluation only.` 评估水印（本例 44 个）。
8. 审计、ODA 导出 AC1032 DWG、DWG 回读核对实体外廓与标注。

## 定版结果
- 总长 `610.0`，左右视图总高均 `284.0`
- 两视图实体外廓均 `284.0`，底边同线（不只是标注文字相等）
- 右视图泵轴中心高按校正后实测为 `147.7`
- `kx = 4.228561367`，`ky = 4.025108742`
- 14 条长度标注全部等于对应尺寸线实测值
- audit `0/0`，DWG 回读实体与标注一致

命令：
```
python src/real_mm_engine.py output/25QYL-2SL_clean.dxf output/real_mm.dxf
```
